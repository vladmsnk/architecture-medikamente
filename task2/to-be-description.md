### Обзор целей

Цели по безопасности
1) Не передавать в контрактах конфиденциальные данные в открытом виде
2) Внешние пользователи не должны мочь получать информацию по API
3) Внутренние пользователи должны видеть только собственные данные
4) Предоставить публичное API, которое позволит легко интегрироваться к системе
5) Использовать AI для определения перс. данных, отслеживания утечек данных и тд

Необходимо разработать
1) Портал для клиентов.
2) Портал для сотрудников ресепшена.
3) Платёжный шлюз.
4) CRM для сбора данных о клиентах.
5) Интеграцию с лабораторией анализов.

Описание Архитектуры
1) Используем API Gateway для маршрутизации всех запросов. 
Также API Gateway будет выступать в качестве Identity Access Proxy (IAP). 
2) API Gateway интегрируется с IdP (реализация OpenID connect) системой, которая будет использоваться для осуществления аутентификации пользователей.
3) API Gateway интегрируется с самописной Identity Access Management (IAM) системой, где будут храниться ABAC политики. 
ABAC политика будет выглядеть примерно так:
```yaml
PolicySet:
  - id: “PatientOwnRecord”
      effect: “Permit”
      description: “Пациент может читать только свои собственные данные”
      target:
        resource:
          attributes:
            dataTag: “Confidential”        # метка ресурса
            patientId: “${resource.ownerId}”
        subject:
          attributes:
            role: “Patient”
            userId: “${subject.userId}”
      condition: “subject.userId == resource.ownerId”
```
4) Все данные по пациентам хранятся в одной СУБД PostgreSQL, для обращения к данным будет реализован сервис "Портал для клиентов".
5) Также в эту СУБД будет сохранять данные CRM 
6) Атрибуты пользователей (сотрудники, доктора, пользователи) и информациях по их учетным записям хранятся, например, в AD и интегрирована с IdP
7) Портал для клиентов позволяет: Выбрать и записаться к врачу, посмотреть предстоящие визиты, посмотреть прошедшие визиты, посмотреть результаты анализов
8) Портал для сотрудников ресепшена позволяет: подтвердить или отклонить запись, отслеживать доступность докторов
9) Платёжный шлюз интегрирован с порталом для клиентов. Все счета на оплату приходят в портал
10) На стороне лаборатории реазилуется сервис, который получает данные из мед. центра. Интеграция осуществляется по единому контракту
11) Через API gateway отслеживаются все операции по изменениям данных, собираются логи, которые отправляются в SIEM
